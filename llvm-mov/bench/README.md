# bench — llvm-mov vs movfuscator

Side-by-side ELF comparison of the two mov-oriented backends on the
same C source. Sources come from
[`../../movfuscator-wasm/tests/fixtures/`](../../movfuscator-wasm/tests/fixtures/)
so both pipelines start from identical input. Results live in
[`results.md`](results.md), regenerated by [`run.sh`](run.sh) and
committed for diffability across PRs and CI.

## Fixtures

Each fixture targets a different legalize-stage surface so a future
bench-check diff isolates which stage moved the numbers:

| fixture          | source                                  | exercises |
|------------------|-----------------------------------------|-----------|
| `return0`        | `movfuscator-wasm/tests/fixtures/`      | trivial floor |
| `return42`       | `movfuscator-wasm/tests/fixtures/`      | trivial floor |
| `eq42`           | `bench/fixtures/`                       | 7c2 (CMP+Jcc EQ/NE) |
| `bitops`         | `bench/fixtures/`                       | 7b1 (AND/OR/XOR) |
| `sum10`          | `movfuscator-wasm/tests/fixtures/`      | 7a (ADD chain) + signed cmp (untouched) |
| `fib10`          | `bench/fixtures/`                       | 7a + 7c1 + signed cmp (untouched) |

Fixtures live in either `bench/fixtures/` (llvm-mov-specific) or the
shared `../movfuscator-wasm/tests/fixtures/` (used by both
subprojects). The runner searches `bench/fixtures/` first so an
llvm-mov override takes precedence on name collisions.

## Pipelines

| backend | pipeline |
|---|---|
| llvm-mov | `clang -m32 -emit-llvm -S` → `llvm-mov-llc -mtriple=mov-…` → `as --32` → `ld -m elf_i386 -static --gc-sections` |
| movfuscator | `movcc <source.c> -o <ELF>` (LCC-based, host-linked) |

`--gc-sections` is important for the llvm-mov side: the byte-add /
bitwise / shift lookup tables live in dedicated `.rodata.__mov_*`
sections that the linker drops when unused, so a `return 42;`-style
fixture doesn't pay the ~256 KiB rodata bill for the ADD tables.

## Metrics

| metric | how |
|---|---|
| total ELF (bytes) | `stat -c %s` on the linked file |
| `.text` size | sum of `objdump -h` Size column for `.text*` |
| `.rodata` size | sum of `objdump -h` Size column for `.rodata*` |
| mov count / total | `objdump -d -Mintel` of `.text`, mnemonic column |
| non-mov mnemonics | what's still in `.text` outside the mov family |

A ratio of `1.0` (100%) means strictly mov-only in `.text`. llvm-mov
reaches this in stage 7d (CALL/RET + prologue/epilogue); at the time
of this writing (through stage 7b), the leftover opcodes are
`call int pop push ret sub` (the `_start` wrapper plus the
function prologue/epilogue) and, for branching fixtures,
`cmp/j*` (CFG legalisation lands in stage 7c).

## Usage

```
make bench                            # regenerate bench/results.md
./bench/run.sh return0 return42 …     # specific fixtures
make bench-check                      # CI: regression-check vs committed baseline
```

Prerequisites: `make build` (for `bin/llvm-mov-llc`),
`make -C ../movfuscator-wasm setup build-native` (for `movcc`),
and `hyperfine` on PATH (for the runtime row).

## As an optimisation regression test

`bench/results.md` is **committed** and `make bench-check` re-runs the
bench, diffs against the committed numbers, and fails on any
divergence in the deterministic rows (ELF/section sizes, mov counts,
non-mov mnemonic sets). The runtime row and the generation timestamp
are intentionally excluded from the comparison — runtime is too
noisy for a hard threshold and timestamps trivially differ.

`make bench-check` is wired into CI alongside `make test-exec` etc.,
so any silent codegen regression (or unintended growth in the
fixture's `.text`/`.rodata`/mov-count) blocks the PR with a clear
diff:

```
bench-check: drift detected vs committed baseline

@@ -14,7 +14,7 @@
 | metric | llvm-mov | movfuscator |
 |---|---:|---:|
-| total ELF (bytes) | 4656 | 10221108 |
+| total ELF (bytes) | 9999 | 10221108 |
```

When the change IS intentional (an optimisation, or a deliberately
larger codegen shape), the developer regenerates the baseline:

```
make bench
git add bench/results.md
```

and commits it alongside the implementation. The PR diff then shows
exactly what changed — every `mov` shaved off a byte-chain rewrite
or every byte trimmed from the `.text` shows up in the bench delta.
This makes mov-count and binary-size optimisations a first-class,
reviewable concern rather than something you have to take on faith.

## Roadmap

- Stage 7c lands → branching fixtures (`sum10`) get mov-only `.text`
  (non-mov column shrinks to just the prologue mnemonics)
- Stage 7d lands → mov ratio reaches 100% (modulo `int 0x80` in
  `_start`, which lives in `_start.o`, not the fixture's `.o`)
- Multi-file fixtures (`multi-add` + its helper) will need pipeline
  support — the runner currently compiles only the named source file.
